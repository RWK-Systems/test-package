A configurable Windows installation simulator built for packaging engineers.

What It Is

Test Package is a purpose-built Windows application that simulates real-world software installation behaviors. Unlike repurposing production apps like 7-Zip or Notepad++ for testing, Test Package was designed from the ground up to exercise the specific installer behaviors that packaging tools need to handle — registry writes, file associations, services, scheduled tasks, environment variables, and more.

Every feature is independently toggleable through a single configuration file. Need to test how your repackaging tool handles a service installation combined with a custom URI protocol? Toggle those on. Need a clean file-only install? Turn everything else off. One tool, infinite test scenarios.

Why It Exists

Software packaging engineers spend significant time validating that their tools correctly capture, transform, and deploy application installers. The challenge: most test applications weren't built for testing. They exercise a narrow set of installer behaviors, they can't be reconfigured without rebuilding, and they introduce variables that obscure whether a failure is in the tool or the test app.

Test Package eliminates that uncertainty. It provides a known, deterministic, fully configurable installation so engineers can isolate exactly what they're testing. When something fails, you know the problem is in your tooling — not your test subject.

How It Works

Configure

Edit config.ini to define exactly what your test installation should do. Choose from 15+ independently configurable features:

Feature Description
Test FilesCreate marker files in configurable locations
Registry EntriesWrite to HKCU, HKLM, or HKCR with custom keys and values
Desktop & Start Menu ShortcutsStandard Windows shortcut creation
File AssociationsRegister custom file types (.tpkg, .tpkx, etc.)
Context MenusAdd right-click shell menu entries
Environment VariablesSet user or system-level variables
Windows ServicesInstall and configure test services
Scheduled TasksCreate Windows scheduled tasks
Firewall RulesAdd inbound/outbound firewall rules
URI Protocol HandlersRegister custom protocol schemes (e.g., testpkg://)
Active SetupPer-user setup triggered on logon
App PathsRegister for Windows Run dialog access
Startup EntriesRegistry or Startup folder auto-launch
Font InstallationInstall fonts to the Windows Fonts directory

Install

Run test-package.exe to launch a multi-page installation wizard. The wizard pages themselves are configurable — show or hide the EULA, component selection, install context picker, and more. Supports both per-user and per-machine installation contexts.

Every action the installer takes is recorded in an install-manifest.json file, giving you a complete, machine-readable record of what was installed and where.

Verify

After installation, the Test Package application launches a context viewer that displays:

  • Execution context — current user, admin status, integrity level, .NET version
  • Installation details — install path, context, date, enabled components
  • Artifact verification — real-time status checks on every file, registry entry, and feature created during install

Uninstall

Use the built-in Uninstall button or run from the command line to cleanly reverse every installation action. The uninstaller reads the manifest and methodically removes files, registry entries, shortcuts, services, tasks, firewall rules, and everything else. Optionally configure intentional leftovers to test how your tools detect incomplete uninstallation.

Testing Scenarios

Repackaging Validation

  1. Set config.ini with desired features enabled
  2. Run the installer while your repackaging tool captures
  3. Build the repackaged output
  4. Deploy and verify with the context viewer

Application Virtualization

  1. Capture the install with your virtualization tool
  2. Run the virtual package
  3. Verify file/registry isolation in the context viewer

Incomplete Uninstall Detection

  1. Enable IntentionallyLeaveFiles and/or IntentionallyLeaveRegistry in config
  2. Install and uninstall
  3. Verify your tool detects the orphaned artifacts
